# Delivery roadmap

## Completed in this MVP source drop

- Phase 0: comparative overlay/source research and explicit no-scraping/no-packet decision.
- Phase 1: Tauri three-window shell, global shortcut registration, transparency/topmost/click-through and persisted window state.
- Phase 2: SQLite schema, migrations, seed, FTS5, typed commands and browser fallback.
- Phase 3: local Wiki/search result experience with RU/EN/provenance fields.
- Phase 4: GS-based roadmap and “Почему?” explanations.
- Phase 5: persistent manual profile and item state.
- Phase 6: persistent Daily/Weekly UI.
- Phase 7: initial Sorcerer module shell and source/version warnings.
- Phase H/I: deterministic recommendation engine, Advisor UI and compact top actions.
- Phase J/L: provider abstraction, source status, version/check history and safe manual-only defaults.
- Multi-character profiles, all-eight-class registry, build/stat pages and split reference/user databases.

6. Benchmark startup/RAM/idle CPU/search and run long-session soak tests.
7. Add installer artwork, code signing, release CI and portable packaging documentation.
8. Only after documented permission, evaluate character import or external DPS-meter read-only integration as optional modules.

## MVP acceptance path

Launch → `Alt+Q` → search “Кромеда” → see item/boss/instance → edit GS → roadmap changes → mark item obtained/favorite → close/reopen → SQLite restores state. The source implements this path; a Windows Rust toolchain is required for native acceptance testing.
